# SCRUM-119 / SCRUM-28 validation — 29 October 2026

## English

**Result:** Local acceptance passed on the PR #1 candidate. This report covers external links and the parent inline-formatting suite; it does not certify the entire application or cloud persistence.

**Defect fixed:** Inline code rendered Markdown emphasis within code spans. A note containing backtick-delimited **bold** and link syntax showed bold formatting inside the code element. The renderer now escapes the code body without applying Markdown marks. A unit contract first reproduced the failure, and a browser regression verifies the literal text, absent nested links/elements, and unchanged content after reload.

**Executed evidence:**

- Inline safety contracts: 23 passed, 0 failed.
- Production TypeScript/Vite build: passed. ESLint: passed.
- Chrome 156.0.8078.49: all 33 SCRUM-28 browser scenarios passed in 7.2 minutes, no retries, skips, or flaky results. This includes card, fused note, canvas, table, unsafe URL and HTML paste handling, toolbar edit/unlink/cancel, Enter, undo/redo, local reload, and the new regression.
- Edge 156.0.4314.50: 8 targeted scenarios passed. Chrome at 1024×640: 8 targeted scenarios passed. These cover external URL rendering, unsafe content, link toolbar on all three surfaces, HTML paste, and the new regression; no retries, skips, or flaky results.
- Before isolating the PR candidate, a repeated focused Chrome run passed 14/14 on the main local checkout. The first candidate suite attempt was interrupted after Vite blocked font assets from a dependency junction (HTTP 403), causing the browser error collector to fail. A test-only Vite override admitted those assets for the final green runs and was removed before the PR change. The lockfiles in both checkouts were SHA-256 identical.

**Artifacts:** candidate-core-33.json and candidate-cross-browser.json in this folder contain per-case results and browser metadata. The original October 22 evidence, including Firefox and Windows WebKit, remains under qa/scrum-28. The new fix was verified on Windows Chrome/Edge; a fresh Linux, Firefox, WebKit, and macOS Safari run is not claimed here. PR #1 is the linked integration candidate. Browser-local IndexedDB persistence is covered; authenticated Supabase/cloud saving is outside this ticket.
