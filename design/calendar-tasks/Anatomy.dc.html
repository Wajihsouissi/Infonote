Cards fill, tasks mark

A day cell already reads a card as a flat wash of its lane's hue. Tasks cannot use the same device — five tasks on one day would fill the tile edge to edge and the hue would stop meaning anything. So a task keeps the hue but spends it on a 2 px spine, the same signal the tray row already uses for an accented card, and carries a real tick box instead of a fill.

The two objects

Card chipFlat wash at 12% of the lane hue. Gains a done/total badge when the card holds tasks. Kanban calendar1/5
Task chipNo fill. Spine in the parent card's hue, 12 px tick box, 11 px text. Granularity switch

Task states

HoverThe row takes the hover wash; the box previews green so the tick target is obvious. Task chips on the grid
DoneGreen box, struck text, spine at half opacity. Green, not accent — accent is one hue off overdue. Day-cell drop target
OverdueSpine, box and text go danger over a 10% wash. The only task state that adds a fill. Solar icon attribution
SubtaskIndented 14 px, spine at 45% — the same step KanbanCard's checklist already draws. Overdue and done states
DraggingThe row left behind sits at 55% with a dashed box; the day cell under the cursor takes the accent wash. Day sheet layout

Order inside a day

Cards first, in byBoardOrder — the board's own comparator, so the calendar never disagrees with the lanes about which card is first. Then each card's tasks in body order directly beneath it, so a task is always adjacent to the card it belongs to. Tasks whose card has no chip on this day (the card is dated elsewhere) sort last, grouped by card. Done tasks stay in place rather than sinking — a day you finished should look finished, not reordered.

What this costs

The day cell grows from 104 px to 132 pxFive rows of content instead of three. Six week rows are still fixed, so the node's mirrored height stays stable — it just settles at a taller constant. Month view goes from 624 px of grid to 792 px.
Two tick vocabularies exist today and one has to goKanbanCard.box ticks in --ok green; CardTasks.taskBox ticks in --accent red. On a calendar where red already means overdue, red cannot also mean done. Green wins; the task modal moves.
Only notes can carry tasksbuildCalendarIndex already excludes blocks and fused notes for having no date fields. Task chips inherit that limit exactly — no new exclusion to explain.
